# loci design

Read the project guide at [`../../../docs/interaction-design.md`](../../../docs/interaction-design.md) from the installed
`.agents/skills/loci-design` directory before making design decisions. Treat that guide as
the routing document; do not copy its token table into this skill.

Use the served `resources/public/index.html` as the current visual and behaviour authority.
Use `docs/product-requirements.md` for proposed direction. Mark current implementation,
product direction, and v3 study separately.

Preserve the one focused Space surface, LEAP as one general entry function alongside
contextual Space/Table controls, notebook outline cells, reusable Items and functions,
clear View versus transformation effects, reachable Action
context, separate approval, and Record versus Recall. Keep prompts, exact inputs, actor,
version, and result reachable near durable work.

When proposing a change, check the guide's review list. Do not add deferred product scope,
turn fixture details into rules, or treat a mockup shortcut or current gap as a requirement.
