# ✧ Suggest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace **⌘ Deep-dive** with **✧ Suggest** — the agent proposes two or three
questions worth pursuing, you edit or refuse them, and you choose whether the answers land
in new notebooks or in this one.

**Architecture:** `deep-dive!` splits along the seam it always had: `suggest!` (digest +
propose, **writes nothing**) and `run-suggestions!` (takes the curated list plus a
destination). Two endpoints, both through the existing jobs layer. The shell shows the
proposals in the modal it already uses for Ask.

**Tech Stack:** Clojure (`src/loci/server.clj`), vanilla JS (`resources/public/index.html`),
`clojure -M:test`, `npm run test:browser`.

**Spec:** `docs/superpowers/specs/2026-08-06-suggest-design.md`

---

## Context for every task

loci is an event-log substrate with a vanilla-JS shell. Today `deep-dive!`
(`src/loci/server.clj:957`) does all of this in one unbroken breath: builds a digest of the
notebook, asks the agent for subtopics, then spawns a notebook per subtopic and researches
each. One click, three researched notebooks, on questions you never saw.

Measured on the live corpus it is the most productive verb in the app — six of the
twenty-one notebooks came from it — and the one that scatters attention hardest. The
capability is right; the absence of consent is the problem.

**Two rules that must survive this change:**

1. **`suggest!` commits zero events.** Proposing must not touch the substrate at all — not a
   reversible event, no event. This is the whole point of the feature.
2. **What you approved is what runs.** `run-suggestions!` takes the curated, possibly
   edited items and does **not** re-ask the agent or re-read the originals.

**Never point a test or a scratch server at the repo's `data/` directory** — it is the
user's real substrate (`md5 e7a6eecdff7bb44ad6b959bb1a7fb7c6`). Tests use `sub/fresh-store`;
the browser harness mkdtemps its own `LOCI_DATA`.

**Verification budget (this matters).** Run sabotage checks against a *single test file*
(`clojure -M:test` is whole-suite, so use it sparingly; `node --test test/browser/x.test.mjs`
for one browser file). Batch independent breaks into one run. Run both full suites **once**,
at the end. A previous feature on this repo burned 52 minutes running the full browser suite
nine times for five sabotages; do not repeat that.

```clojure
;; ---- suggest: the agent proposes, you decide ----
;; This was deep-dive!, which proposed AND spawned AND researched on one click.
;; The capability was right and the consent was missing, so it splits here: the
;; half that reads and proposes writes nothing, and the half that acts takes only
;; what you approved.
(defn suggest!
  "Questions worth pursuing in this notebook. Commits NOTHING — not a reversible
   event, no event. Dismissing leaves the substrate untouched."
  [st space]
  (try
    (let [sp (sub/object st space)]
      (if-not (= :space (:kind sp))
        {:error (str "not a notebook: " space)}
        (let [digest (str (->> (nb/cells-of sp) (keep #(sub/object st (:ref %)))
                               (map obj-digest) (str/join "\n"))
                          (remembered-context (str (:title sp) " " (get-in sp [:value :intent]))))]
          {:proposals (vec (take 3 (agent/propose-subtopics
                                     (:title sp) (get-in sp [:value :intent]) digest)))})))
    (catch Exception e {:error (.getMessage e)})))

(defn- fresh-dd-id
  "One past the highest space:dd-N, and never one that already exists. The old
   form derived the id from the TOTAL notebook count, which had nothing to do
   with the dd sequence; the day anything deletes a notebook that :put would
   overwrite a notebook in silence."
  [st]
  (let [highest (->> (nb/notebooks st)
                     (keep #(some->> (:id %) (re-find #"^space:dd-(\d+)$") second parse-long))
                     (reduce max 0))]
    (loop [n (inc highest)]
      (if (sub/object st (str "space:dd-" n)) (recur (inc n)) (str "space:dd-" n)))))

(defn run-suggestions!
  "Research the questions you approved. `destination` is \"new\" (one connected
   notebook each, as deep-dive did) or \"here\" (cells in this notebook, exactly
   as pressing Research repeatedly would).

   Not atomic across items, deliberately: three researches are three commits, and
   a failure on the second leaves the first in place. A partial result is worth
   keeping and is individually undoable."
  [st space items destination]
  (try
    (let [sp (sub/object st space)]
      (cond
        (not= :space (:kind sp)) {:error (str "not a notebook: " space)}
        (empty? items)           {:error "nothing to research"}
        (not (#{"new" "here"} destination))
        {:error (str "unknown destination: " destination)}
        :else
        (let [ptags (inherit-tags st space)
              done  (vec (for [{:keys [title intent query]} items]
                           (if (= "new" destination)
                             (let [sid (fresh-dd-id st)]
                               (sub/commit! st {:op :put :id sid
                                                :value {:id sid :kind :space :title title
                                                        :value (cond-> {:intent intent :cells []
                                                                        :spawned-by {:space space :prompt query}}
                                                                 (seq ptags) (assoc :tags ptags))}})
                               (research! st sid query)
                               sid)
                             (do (research! st space query) space))))]
          {:state (state-payload st) :ran done :destination destination})))
    (catch Exception e {:error (.getMessage e)})))
```

**Note on `a-failure-midway-keeps-what-already-landed`:** the `for` above is lazy and wrapped
in `vec`, and the whole body is inside `try`, so a throw on item 2 aborts the rest and the
outer `catch` returns `{:error …}` while item 1's commits stand. Verify that is what actually
happens — if the laziness means item 1's `research!` never ran at all, restructure to an
eager `reduce` and say so.

Add near `startAsk` (`:787`). It reuses the existing `.modalcard` / `.modal-h` / `.modal-b` /

```javascript
// The agent proposes; you decide. Every row is editable, because the phrasing is
// usually close and rarely exact, and refusing a good question over one wrong
// word is a real loss. Two destination buttons, never one mutating button: the
// outcomes differ sharply and a mis-click is expensive.
function openSuggest(i,sp,proposals){
  const rows=proposals.map((p,k)=>
    '<div class="sgrow"><label><input type="checkbox" data-k="'+k+'" checked> '+
    '<b>'+esc(p.title)+'</b></label>'+
    '<input class="sgq" data-k="'+k+'" value="'+esc(p.query||'')+'"></div>').join('');
  modal.innerHTML='<div class="modalcard" style="max-width:720px"><div class="modal-h">'+
    '<span style="font-family:var(--mono);font-size:11px;color:var(--accent);border:1px solid var(--accent-line);border-radius:6px;padding:2px 7px">SUGGEST</span>'+
    '<span class="q">questions worth pursuing in “<b>'+esc(sp.title)+'</b>”</span></div>'+
    '<div class="modal-b">'+rows+'</div>'+
    '<div class="modal-f">'+
      '<button class="btn sm" id="sgNew"></button>'+
      '<button class="btn sm" id="sgHere"></button>'+
      '<button class="btn ghost sm" id="sgDismiss">Dismiss</button>'+
      '<span style="font-size:11.5px;color:var(--muted)">nothing has been written yet</span>'+
    '</div></div>';
  modal.classList.add('on');
  const picked=()=>[...modal.querySelectorAll('.sgrow')].map((row,k)=>{
    const on=row.querySelector('input[type=checkbox]').checked;
    return on?{title:proposals[k].title,intent:proposals[k].intent,
               query:row.querySelector('.sgq').value.trim()}:null;
  }).filter(Boolean);
  const relabel=()=>{ const n=picked().length;
    modal.querySelector('#sgNew').textContent='Research '+n+' in new notebook'+(n===1?'':'s');
    modal.querySelector('#sgHere').textContent='Research '+n+' in this notebook';
    modal.querySelectorAll('#sgNew,#sgHere').forEach(x=>x.disabled=(n===0)); };
  relabel();
  modal.querySelectorAll('.sgrow input[type=checkbox]').forEach(c=>c.addEventListener('change',relabel));
  modal.querySelector('#sgDismiss').addEventListener('click',closeModal);
  const go=async dest=>{
    if(TIME){ showToast('time mode — ↩ now to edit'); return; }
    const items=picked(); if(!items.length) return;
    closeModal();
    const b=document.getElementById('body'+i);
    if(b) b.innerHTML='<div class="sec-h">researching</div><div style="color:var(--muted);font-size:13px">'+
      items.length+' question'+(items.length===1?'':'s')+' — this takes a while. You can keep working; results land when ready…</div>';
    let res; try{ res=await API.suggestRun(sp.id,items,dest); }
    catch(e){ showToast('suggest: network error'); renderBody(i); return; }
    if(res.error){ showToast('suggest: '+res.error); renderBody(i); return; }
    pollJob(res.job, r=>{
      if(TIME){ showToast('agent finished — ↩ now to see it'); return; }
      if(r.error){ showToast('suggest: '+r.error); if(mode==='focus'&&focusIdx===i&&!openId) renderBody(i); return; }
      applyState(r.state); safeRebuild();
      showToast(dest==='new'
        ? 'Spawned '+r.ran.length+' connected notebook'+(r.ran.length===1?'':'s')
        : 'Researched '+r.ran.length+' question'+(r.ran.length===1?'':'s')+' here');
    });
  };
  modal.querySelector('#sgNew').addEventListener('click',()=>go('new'));
  modal.querySelector('#sgHere').addEventListener('click',()=>go('here'));
}
```
