### Task 1: Undo a merge

**Files:** modify `src/loci/memory.clj`, `src/loci/server.clj` (route); tests

A survivor carries `:merged-from` — each entry holding the absorbed fact's `:id`, `:fact`,
`:strength`, `:entities` and `:source`. The data supports undoing a merge; there is no gesture.

**The trap that makes this non-trivial.** A restored fact has **no `:vec`** (merge drops it).
The next sweep embeds it, merge compares it against the survivor it was just split from, finds
the same high cosine, and folds it straight back. **Without suppression the gesture does
nothing at all**, and would look like a bug in the UI rather than in the model.

So a restored fact records that it must not be re-merged with that survivor, and
`merge-similar!` honours it. Decide the representation — a set of ids on the restored fact, on
the survivor, or on both — and **say in a comment why you chose it**. Consider: what happens
if the survivor is later itself absorbed by a third fact?

- [ ] **Step 1: Write the failing tests.**
  - `unmerge!` restores the absorbed fact as a live fact with its stored text, strength,
    entities and source, and removes that entry from the survivor's `:merged-from`
  - the survivor's `:strength` drops by the absorbed fact's strength, floored at 1
  - **the pair is not re-merged**: embed both, run `merge-similar!`, and they stay separate.
    This is the test that makes the feature real rather than decorative
  - other pairs still merge normally — suppression is per pair, not a global off switch
  - unmerging an id that is not in `:merged-from` is refused with a message, not an exception
  - it survives a reload: the restored fact and the suppression are both in the file
  - `:ts` cannot be fully restored — merge took the newer and the pre-merge value is not
    stored. Pick a defensible value, **document the loss**, and pin it. Do not pretend.

- [ ] **Step 2-4: fail, implement, green.** Add `POST /api/memory-unmerge {survivor, absorbed}`.

- [ ] **Step 5: Prove it bites.** One batch, distinct tests: drop the suppression (the
  not-re-merged test must fail); do not decrement strength; let an unknown id through.

- [ ] **Step 6: Commit** — `feat: a merge can be undone, and stays undone`

### Task 2: The pane's denominator, and the unmerge gesture

**Files:** modify `src/loci/server.clj` (`memory-payload`), `resources/public/index.html`,
`test/browser/memorypane.test.mjs`; tests

The status line reads `12 of 80 awaiting` only on a browse, because the payload carries no
total and `facts` is the ranked top 20 under a query. Add `:total` — the count of live facts,
independent of the query — so the line is true of the memory in both cases.

Then wire Task 1's endpoint: each entry in the expanded `+N merged` list gets an **unmerge**
control.

- [ ] **Step 1:** `:total` on the payload, with a test that it is the live-fact count and not

- [ ] **Step 2:** the status line uses it in both cases. Assert on **text content**.
- [ ] **Step 3:** an unmerge control per absorbed entry; clicking it calls the endpoint and

  names the right survivor and absorbed id, and the pane reflects the result.
- [ ] **Step 4: Prove it bites** — make `:total` follow the page rather than the memory; drop
  the control. Distinct tests.
- [ ] **Step 5:** both suites once. **Commit** — `feat: the pane counts the whole memory, and can undo a merge`

### Task 3: LEAP's Enter

**Files:** modify `resources/public/index.html`; `test/browser/semanticleap.test.mjs`

`deepen()` is called on Enter, but **Enter activates the selected row** and every acting path
calls `closeLeap()`, which drops the response. So the Enter path is dead intent: it fires a
request whose result is thrown away.

- [ ] **Step 1: Find out what is actually true** before changing anything. Read the keydown
  handler and `act()`. Is there always a selected row? Is there any state in which Enter does
  *not* act? Report what you found.
- [ ] **Step 2: Then choose, and justify it.** Either make Enter genuinely useful (e.g. it
  deepens when nothing is selected, if that state exists) **or delete the dead call**. Removing
  intent that cannot work is a fix, not a retreat — an Enter that silently issues a discarded
  request is worse than no Enter handling, because it reads as a feature.
- [ ] **Step 3:** a browser test pinning whichever behaviour you chose, so the next reader does
  not restore the other. **Do not** assert on request counts alone — a request that is made and
  discarded is exactly the defect.
- [ ] **Step 4: Prove it bites. Step 5:** both suites once.
- [ ] **Step 6: Commit** — `fix: LEAP's Enter does something, or nothing, but not the appearance of something`

### Task 4: A smaller image with `jlink`

**Files:** modify `Dockerfile`, `README.md`

Measured: the image is **428 MB**, of which ~205 MB is the Temurin JRE layer, ~59 MB apt, and
~100 MB Ubuntu. The application jar is 63.9 MB. A `jlink`ed runtime carrying only the modules
loci needs should remove **150–200 MB**.

- [ ] **Step 1: Find the module set empirically**, with `jdeps` against the slim jar — do not
  guess a list. Datalevin uses JNA and native access; `loci.embed`/`agent` use HTTP; the
  substrate uses nio. Report the modules you found and how.
- [ ] **Step 2: Build a runtime** in the build stage (`jlink --add-modules … --strip-debug
  --no-man-pages --no-header-files --compress=…`) and copy it into a minimal base. Keep the
  non-root user, the healthcheck, `ENV LOCI_DATA`/`PORT` and the `VOLUME`.
- [ ] **Step 3: Verify it actually runs, which is the whole point.** In the container: LMDB
  opens, `/api/state` answers, a write via `/api/connect` survives `docker restart` on a named
  volume, and the healthcheck reports healthy. **If `jlink` breaks Datalevin's native access
  or the reflection Clojure needs, keep the JRE base and report that** — a smaller image that
  does not run is not an improvement, and reporting the failure honestly is the successful
  outcome of this task.
- [ ] **Step 4: Re-run the secret scan.** Flattened `docker export`, decompress jar entries,
  with a positive control proving the search works. Zero hits on any key.
- [ ] **Step 5:** report before/after image size. **Commit** — `build: a jlinked runtime, if it earns its place`

**Use a throwaway volume, image tag and port.** The user's `loci:latest`, `loci-data`,
`loci_loci-data` and port 7777 are theirs — do not touch them. Clean up everything you create.
