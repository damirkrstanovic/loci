  - `distribution` returns min/median/mean/p90/p95/p99/max over all pairs
  - it refuses a corpus of fewer than ~10 items with an honest message rather than returning

### Task 3: The cell-operation race

**Files:** modify `src/loci/server.clj` (`notebook-op!`, ~`:414-429`); tests

`notebook-op!` reads a notebook's cells, computes the new vector, and writes the whole thing —
the same read-modify-write `append-cell-event` stopped doing. Two at once and one is lost. The
existing comment says reorder and delete have no commutative apply-time form, which is true,
**and is not a reason to lose data.**

- [ ] **Step 1: Write the failing test.** N threads issuing cell ops on one notebook
  concurrently (mix of `add-text`, `edit-text`, `move`, `delete`), released together by a
  `CountDownLatch`. Assert **no operation is silently lost**: every op either applied or is
  reflected in the final state, and the cell count matches what serial application would give.
  Report the pre-fix loss count.

- [ ] **Step 2: Run, watch fail.** Report the real number lost.

- [ ] **Step 3: Implement — take a lock, do not invent a merge.**

  Wrap the read-modify-write in `notebook-op!` in a `locking` on a server-held monitor. This
  serialises concurrent cell edits so the second sees the first's result; last-writer-wins on
  *intent* but **no cell is lost**, which is the actual defect.

  A lock is right here and a new apply-time op is not: these come from a person clicking, not
  from agent jobs in parallel, so contention is negligible and throughput is not the concern.
  Say exactly that in the comment, replacing the existing "left as is on purpose" one.

  Use one monitor per notebook id (a small interned map), not one global lock, so editing two
  notebooks does not serialise — and say why. Do **not** hold the lock across an agent call or
  any I/O beyond the commit.

- [ ] **Step 4: Green.** **Step 5: Prove it bites** — remove the lock, the test must fail with
  the loss count from Step 2. Restore.

- [ ] **Step 6: Commit** — `fix: cell operations serialise, so two at once stop losing one`
