# Per-table lake GC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user can see how much space each table's historical versions occupy and reclaim them
one table at a time, and a table whose rows are gone degrades for that object alone rather than
breaking whatever operation touched it.

**Architecture:** Two phases. Phase 1 makes seven reader sites tolerate an unreadable table — no GC
involved, valuable alone, and the prerequisite that makes Phase 2 safe. Phase 2 adds
`loci.lakegc`, which classifies every lake table against the log into current / in-window /
reclaimable / orphaned, reclaims by `DROP TABLE` plus per-file Parquet deletion, and exposes it
at `GET /api/storage` and `POST /api/storage/reclaim` with a shell panel.

**Tech Stack:** DuckDB 1.5.5 + the `ducklake` extension via `org.duckdb/duckdb_jdbc`; the existing
`loci.substrate` log, `loci.tablestore` protocol and `loci.lake` connection.

Spec: `docs/superpowers/specs/2026-08-17-lake-gc-design.md`.

## How to run things in this project

Read `.claude/skills/clojure-repl-dev` and `CLAUDE.md` first. The short version, because it
changes every "Run:" step below:

- **Do not start a JVM to run Clojure.** `clojure -M -e` costs ~25 s before the first form
  evaluates. Use `mcp__clojure-mcp__clojure_eval` against the running nREPL.
- **Reload a protocol namespace BEFORE its implementors** — `loci.tablestore` → `loci.lake` →
  `loci.chunks` → everything else. The other order orphans records with
  `No implementation of method: …`.
- **Load test namespaces cleanly** with `(remove-ns 'the.ns)` plus dropping the symbol from
  `*loaded-libs*`, then `require`. `use-fixtures` writes namespace *metadata* that `(ns …)` does
  not clear, so a fixture sabotage done with `:reload` silently lies. `defonce` needs `ns-unmap`
  for the same reason.
- **Only one connection to a given lake directory per JVM.** A second `open-lake!` on the same
  dir fails with `Unique file handle conflict`. `close!` every lake you open.
- **Do not force `loci.lake/lake` bare at the REPL.** `requiring-this-namespace-opens-no-lake`
  asserts it stays unrealized. Use `with-redefs [loci.lake/lake (delay lk)]`. Report
  `(realized? loci.lake/lake)` at the start and end of every task.
- `clojure -M:test` is for **one final full-suite run**, not for iteration.
- Both suites must pass: `clojure -M:test` **and** `npm run test:browser`.

**Every task ends with a sabotage step.** Reintroduce the bug the test exists to catch, confirm
the test **fails**, restore, confirm it passes. A test that passes either way is worse than no
test, because it certifies. Report the actual failure output.

**A sabotage that does not bite means one of two things, and they are not the same:** the code is
dead, **or** the environment already supplies what it provides. Distinguish before concluding.
Three implementers on the previous plan hit this.

**A grep is not an invariant.** The previous plan twice declared a set of call sites complete on
the strength of a `grep :kind :table`, and twice a writer was found afterwards — once because the
kind was a function parameter. When a task says "find every site", find them by tracing what the
code does, then use grep to check your list, not to build it.

## The DuckLake API this plan uses

All verified in the REPL 2026-08-17 against the real catalog. **Do not assume any other
`ducklake_*` function exists** — an earlier plan named `ducklake_tables('lake')`, which does not.

```clojure
;; live tables with sizes — ONE query for the whole report.
;; A dropped table is ABSENT here. An inlined table has file_count 0.
"SELECT table_name, table_id, file_count, file_size_bytes FROM ducklake_table_info('lake')"
;; => {:table_name "t_tbl_corpus_1_f0415d12" :table_id 1 :file_count 1 :file_size_bytes 20272}

;; the files of one table, absolute paths — what reclaim deletes
"SELECT data_file, data_file_size_bytes FROM ducklake_list_files('lake', 't_tbl_orders_b5732d7d')"
;; => {:data_file "/home/…/data/lake/files/main/t_tbl_orders_b5732d7d/ducklake-01a0….parquet"
;;     :data_file_size_bytes 14248}

;; dropped tables and WHEN. Note the metadata tables are invisible to duckdb_tables()
;; but are queryable by fully-qualified name.
"SELECT t.table_name, t.end_snapshot, s.snapshot_time
   FROM __ducklake_metadata_lake.main.ducklake_table t
   JOIN ducklake_snapshots('lake') s ON s.snapshot_id = t.end_snapshot
  WHERE t.end_snapshot IS NOT NULL"
;; => {:table_name "t_tbl_x_b3ebeb3b" :end_snapshot 3
;;     :snapshot_time #object[java.time.OffsetDateTime "2026-08-17T11:55:13.750780+02:00"]}
```

**`ducklake_snapshots('lake')`'s `:changes` column contains `org.duckdb.DuckDBArray`**, which
`clojure.data.json/write-str` cannot serialize. Never let it reach a payload. `lake/q` does not
unwrap it — only `q-as` unwraps, and only `JsonNode`.

**Asking the catalog per table costs ~100 ms over 29 tables; batched it is 3.9 ms.** Measured in
Task 4 against the real store. The cost is the **round trip, not the scan** — one whole-catalog
query is 3.38 ms and a single table-filtered one is 3.29 ms. So `lake/dropped-tables` returns the
whole map and `lake/dropped-at` is a lookup into it. **Any new per-table catalog question must be
batched the same way**, especially on `table-catalog`, which runs on every chat turn.

**`clojure.data.json` drops namespaces from keys.** `:table/total` serializes as `"total"` and
`:table/cols` as `"cols"`. Task 10's panel must read the short names.

**`ducklake_list_files` reports only the LIVE `table_id`'s files.** Measured in Task 8: after
`restore-to!`, `ducklake_data_file` holds `{id 0, table_id 1, end 2}` (the tombstoned sibling) and
`{id 1, table_id 2, end nil}` (live), and `ducklake_list_files` names only the second. So deleting
what it reports leaves the pre-restore Parquet on disk, the recreate-denial property fails, and
the bytes become uncollectable because the name leaves `live-tables` on the drop. Reclaim must
select across **every `table_id` that ever bore the name**.

**A DuckLake `DROP TABLE` mints a snapshot** — measured `[0 1 2]` → `[0 1 2 3]`. So a test for
"nothing was expired" must assert the old snapshot ids are a **subset**, not that the count is
unchanged. The count going *up* by one per drop is itself worth asserting: a tombstone is added,
never removed.

**`ducklake_list_files` THROWS for a dropped table** — it does not return empty. Measured
2026-08-17 in Task 2: `Catalog Error: Table with name t_tbl_x_9b26d66a does not exist!`, because
it resolves its argument through the live catalog. **So any code that deletes a table's files
must list them BEFORE the `DROP`.** Task 8's `reclaim!` is written that way; do not reorder it.

**A small table has no Parquet at all.** DuckLake inlines a small insert into `catalog.duckdb`
(`ducklake_inlined_data_*`), so below roughly 10–20 rows `ducklake_list_files` returns nothing
and there is no file to delete. Measured: 2 rows → 0 files, and a read after `DROP` + delete
still **succeeds**; 100 rows → 1 file, and the same read throws `IO Error: Cannot open file`.

**This is a trap for tests, not just for code.** Any test that proves a reader degrades on an
unreadable table must use **100 rows**, or the table it "breaks" is still perfectly readable and
the test passes while exercising the happy path. `lake_test.clj`'s `rows100` fixture exists for
this. Two tasks in this plan were written with 2-row tables and corrected after Task 2 found it.

```clojure
(defn dropped-at
  "When `table` was dropped from this lake, or nil if it was never dropped.

   The catalog is the record, so nothing here keeps a parallel one. DuckLake
   sets `ducklake_table.end_snapshot` on a drop and `ducklake_snapshots` carries
   that snapshot's time, so \"was this reclaimed, and when\" is a question the
   store that did the reclaiming can already answer.

   Returns nil for a name that was never a table at all — absent is not the same
   as reclaimed, and a read that fails for any other reason must stay an error
   rather than being reported to a user as a successful cleanup.

   Note the metadata tables are invisible to `duckdb_tables()` and must be named
   in full."
  [lk table]
  (some-> (first (q lk (str "SELECT s.snapshot_time AS t"
                            "  FROM __ducklake_metadata_lake.main.ducklake_table dt"
                            "  JOIN ducklake_snapshots('lake') s"
                            "    ON s.snapshot_id = dt.end_snapshot"
                            " WHERE dt.table_name = '" table "'"
                            "   AND dt.end_snapshot IS NOT NULL"
                            " ORDER BY dt.end_snapshot DESC LIMIT 1")))
          :t
          (.toInstant)
          (java.util.Date/from)))
```

`table` is interpolated rather than parameterized because every caller passes a handle's
`:table`, which `table-name` generated as `t_[a-z0-9_]*_[0-9a-f]{8}`. If you add a caller that
does not, parameterize it.

Drop the `AND dt.end_snapshot IS NOT NULL` clause. `dropped-at-knows-a-dropped-table` must FAIL
on the first assertion, because a live table would now report a time. Restore.

```clojure
    (let [ts (force ts)
          h  (:value o)]
      (try
        (assoc o :value       (rows ts h {:limit mold-cap})
                 :table/total (row-count ts h))

            ;; count survive because they live on the handle, not in the rows.
            (assoc o :value [] :table/total (:rows h)
                     :table/cols (:cols h) :table/reclaimed at)
            (throw e)))))
    o))
```

In `src/loci/chunks.clj`, `with-samples` is the only place that reaches the lake:

```clojure
(defn- with-samples
  "A handle-backed table, described. Attaches what `texts-of` needs and nothing
   else — the rows are never fetched.

   A table whose rows are gone loses its samples and nothing else: `texts-of`
   falls through to the title, which is the same chunk an untitled-value table
   has always produced. The sweep is whole-substrate and runs on a timer, so one
   unreadable table must never cost more than its own chunk."
  [o]
  (if (tbl/handle? (:value o))
    (let [h (:value o)]
      (try
        (assoc o :table/cols    (vec (take synopsis-cols (:cols h)))
                 :table/samples (tbl/column-samples (force lake/lake) h
                                                    synopsis-samples synopsis-cols))
        (catch Exception e
          (if (tbl/reclaimed-at (force lake/lake) h)
            o
            (throw e)))))
    o))
```

Note `o` unchanged in the reclaimed branch: without `:table/samples`, `texts-of`'s
`(:table :metric)` branch falls to `(not (str/blank? (str title))) [(str title)]`, which is
already how it handles a table it cannot describe.

```clojure
(ns loci.lakegc
  "What each lake table costs, and reclaiming the ones nothing needs.

   Writes never overwrite — every `put-rows!` mints a new lake table — so a
   table refreshed ten times leaves ten lake tables behind. This namespace is
   what tells you that and lets you act on it, one object at a time.

   It issues no SQL of its own; `loci.lake` owns the connection and every query.

   Measured 2026-08-17: DuckLake's own `cleanup_old_files` cannot do this. It
   will not touch a file until every snapshot below its `end_snapshot` is
   expired, and a DuckLake snapshot is catalog-wide, so freeing one object's old
   version always means expiring the snapshots other objects' live handles read
   at — measured, that broke three unrelated handles. `DROP TABLE` plus deleting
   that table's own Parquet frees the same bytes, expires nothing, and leaves
   every other handle reading."
  (:require [loci.lake :as lake]
            [loci.substrate :as sub]
            [loci.tablestore :as tbl]))

(def default-window
  "How much history a reclaim keeps: whichever of these keeps more.

   A version count alone would drop a busy afternoon's work; an age alone puts
   no ceiling on a table rewritten forty times in that afternoon. Taking the
   larger keeps recent work under either reading, and still bounds a table once
   it goes quiet."
  {:versions 3 :days 30})

(defn- event-handles
  "Every `{:table … :object … :ts …}` one event names, **including inside a `:tx`**.

   A `:tx` is several sub-events committed as one undoable step, and
   `tools/save-table!` commits one whenever it also appends a notebook cell. A
   classifier that walked only top-level events would find no handle for those
   tables, call them orphaned, and reclaim rows a live object is still using —
   the worst outcome this namespace can produce. Sub-events carry no `:ts` of
   their own, so they inherit the transaction's.

   Two shapes carry a handle: a `:put` whose value is the whole object, and an
   `:assoc` at `[:value]` whose value is the handle itself (that is how
   `rerun!` refreshes a table)."
  [ev]
  (case (:op ev)
    :tx (mapcat #(event-handles (assoc % :ts (:ts ev))) (:events ev))
    (let [v (:value ev)
          h (cond (tbl/handle? v)          v
                  (tbl/handle? (:value v)) (:value v))]
      (when h [{:table (:table h) :object (:id ev) :ts (:ts ev)}]))))

(defn- handles-in-history
  "Every `{:table … :object … :ts …}` the log has ever named, newest first per
   object.

   From `sub/history` rather than from current state, because `as-of` and undo
   can reach any of them — that is exactly what the window protects."
  [st]
  (->> (sub/history st)
       (mapcat event-handles)
       (group-by :object)
       (into {} (map (fn [[o hs]] [o (vec (reverse hs))])))))

(defn classify
  "`{lake-table {:class … :object … :ts …}}` for every table in the lake.

   Four classes. **current** — named by a handle on a live object; never
   touched. **in-window** — superseded but inside `window`; kept, so undo and
   `as-of` stay exact there. **reclaimable** — superseded and outside it.
   **orphaned** — named by no handle anywhere in the log, which `undo!` produces
   (it deletes the event) and so does a write whose caller died between the lake
   commit and `sub/commit!`. Orphans ignore the window because nothing can ever
   reference them again."
  [st lk {:keys [versions days] :as _window}]
  (let [live    (set (keep #(:table (:value %)) (vals (sub/objects st))))
        by-obj  (handles-in-history st)
        cutoff  (- (System/currentTimeMillis) (* days 24 60 60 1000))
        seen    (into {} (for [[o hs] by-obj
                               [i {:keys [table ts]}] (map-indexed vector hs)]
                           [table {:object o :ts ts :age-rank i}]))]
    (into {}
          (for [{:keys [table_name]} (lake/live-tables lk)
                :let [m (get seen table_name)]]
            [table_name
             (cond
               (nil? m)                    {:class :orphaned :object nil :ts nil}
               (live table_name)           (assoc m :class :current)
               (or (< (:age-rank m) versions)
                   (>= (or (:ts m) 0) cutoff)) (assoc m :class :in-window)
               :else                       (assoc m :class :reclaimable))]))))
```

```clojure
(defn report
  "What every object's tables cost, and what a reclaim would free.

   Walks the log once and asks the catalog for sizes in one query. **Fetches no
   rows** — a storage panel that costs a row read per table would be slower than
   the thing it is reporting on, and DuckDB's JDBC driver is slow row-wise
   (42 ms to walk 1,000×8 cells, measured 2026-08-17).

   `:lake` reports `:files` and `:catalog` separately because `catalog.duckdb`
   never shrinks and was 98% of the lake at fixture scale — a panel showing only
   reclaimable bytes would make a correct reclaim look like it did nothing."
  [st lk window]
  (let [cls   (classify st lk window)
        sizes (into {} (map (juxt :table_name identity)) (lake/live-tables lk))
        bytes #(or (:file_size_bytes (sizes %)) 0)
        objs  (sub/objects st)
        rows  (for [[object ts] (group-by :object (map #(assoc (val %) :table (key %)) cls))
                    :when object
                    :let [by-class (group-by :class ts)
                          recl (concat (:reclaimable by-class) (:orphaned by-class))]]
                {:id      object
                 :title   (:title (get objs object))
                 :versions (count ts)
                 :current  (reduce + 0 (map #(bytes (:table %)) (:current by-class)))
                 :in-window (count (:in-window by-class))
                 :reclaimable (reduce + 0 (map #(bytes (:table %)) recl))
                 :reclaimable-versions (count recl)
                 :orphaned (reduce + 0 (map #(bytes (:table %)) (:orphaned by-class)))
                 :inlined? (every? #(zero? (or (:file_count (sizes (:table %))) 0))
                                   (:current by-class))})
        orph  (filter #(nil? (:object (val %))) cls)]
    {:window window
     :lake   {:files   (reduce + 0 (map :file_size_bytes (lake/live-tables lk)))
              :catalog (.length (java.io.File. (str (:dir lk) "/catalog.duckdb")))}
     :orphaned {:tables (count orph)
                :bytes  (reduce + 0 (map #(bytes (key %)) orph))}
     :tables (vec (sort-by (comp - :reclaimable) rows))}))
```

## Task 8: `lakegc/reclaim!` — drop, then delete the files

**Read this first — a safety property Task 6 established, and `reclaim!` must assert it.**

`classify`'s `cond` tests `(nil? m)` **before** `(live table_name)`. That ordering is deliberate:
it means any gap in `event-handles`' coverage surfaces as a **live table classified `:orphaned`**,
which is loud, rather than as a live table quietly classified `:current`, which would hide the
gap. Task 6's second sabotage demonstrated exactly that — remove the `:tx` branch and a live
table is offered for deletion.

And **orphans ignore the window.** So the single worst thing this feature can do is delete a
table that a live object is still using, and the only thing standing between that and the disk is
`event-handles` having complete coverage of every event shape that can carry a handle.

Therefore `reclaim!` must **refuse, not proceed**, if any table it is about to delete is in the
live set — `(set (keep #(:table (:value %)) (vals (sub/objects st))))`. That is not defence
against a case anyone has hit; it is a cheap assertion that converts a future coverage gap from
silent data loss into a stopped run with a message. Throw or return an `:error`, do not filter and
carry on: if the classifier and the live set disagree, the right move is to stop and be looked at.

Test it by classifying, then hand-editing one entry to `:orphaned` for a table that is live, and
asserting `reclaim!` refuses and deletes nothing.

**Read this too, measured in Task 3.** `lake/sample-cache` memoizes column samples per
`[lk table snapshot cols per-col]`, and the 15-second chunk sweep warms that memo for every lake
table. So **after a reclaim, the memo still serves the reclaimed table's full synopsis** — the
chunk text does not change, its hash does not move, and nothing re-embeds until the process
restarts with a cold cache. Then it costs exactly one embedding and retires nothing.

This is benign and you should not "fix" it: the synopsis is a search aid, it self-corrects on
restart, and invalidating the memo would mean `reclaim!` reaching into another namespace's cache.
But **do not write a test that asserts the chunk text changes right after a reclaim** — in a warm
REPL it will not, and you will chase a bug that is a cache doing its job.

```clojure
(defn table-files
  "The absolute paths of one table's Parquet files, with their sizes.

   Files, not the directory. `restore-to!` is a `CREATE OR REPLACE`, which mints
   a new `table_id` under the **same** table name and directory — measured
   2026-08-17, one directory held a dead and a live Parquet at once — so
   removing a directory can destroy live data. The individual path is the only
   safe unit."
  [lk table]
  (q lk (str "SELECT data_file, data_file_size_bytes FROM ducklake_list_files('lake', '" table "')")))

(defn drop-table!
  "Drop `table` from the catalog. Frees no bytes on its own — a DuckLake drop is
   a versioned tombstone, and the table still reads `AT` a version where it
   existed. `loci.lakegc` deletes the files afterwards; that is what makes it
   real."
  [lk table]
  (x! lk (str "DROP TABLE " table)))
```

```clojure
(defn reclaim!
  "Reclaim one object's out-of-window and orphaned versions. Irreversible.

   `DROP TABLE`, then delete that table's own Parquet files. Never
   `ducklake_expire_snapshots` — expiry is catalog-wide, and freeing one
   object's history that way expires the snapshots every other object's handles
   read at (measured: three unrelated handles broke).

   There is no dry-run flag because `report` is the dry run: it names exactly
   the versions this will delete and the bytes it will free, and this asserts
   the same numbers back."
  [st lk object window]
  (let [cls  (classify st lk window)
        mine (for [[table m] cls
                   :when (and (= object (:object m))
                              (#{:reclaimable :orphaned} (:class m)))]
               table)]
    (if (and (empty? mine) (nil? (sub/object st object)))
      {:error (str "no such object: " object)}
      (let [freed (reduce
                   (fn [acc table]
                     (let [files (lake/table-files lk table)]
                       (lake/drop-table! lk table)
                       (doseq [{:keys [data_file]} files]
                         (clojure.java.io/delete-file data_file true))
                       (+ acc (reduce + 0 (map :data_file_size_bytes files)))))
                   0 mine)]
        {:object object :versions (count mine) :freed freed}))))
```

## The window makes the feature invisible for 30 days — by design, and worth knowing

Found in Task 10. `POST /api/storage/reclaim` calls `gc/reclaim!` with `default-window`
`{:versions 3 :days 30}`, and `classify` keeps a version if **either** the count or the age keeps
it. So on a new instance every version is in-window for a month, `:reclaimable` is 0, and the
panel's reclaim control has nothing to act on.

That is the `max(3 versions, 30 days)` decision working as specified — it was chosen precisely so
a busy afternoon's work cannot be dropped by a version count. The consequence is that the feature
does nothing visible until a table's old versions age past 30 days.

Every server-side test reaches a reclaimable state by passing `{:versions 3 :days 0}` straight to
`gc/reclaim!`, which the HTTP route cannot produce. `sub/commit!` stamps `:ts` with
`(System/currentTimeMillis)` and takes no argument for it, so a browser fixture that needs a
reclaimable state must **age the log in place**. `test/browser/harness.mjs` does that and says why.

Two things not to do about it. Do not let the POST carry a caller-supplied window: that turns one
click into "delete recent history" and undermines the reason the window exists. And do not shorten
the default to make the panel look busier. If the 30 days ever proves wrong, it is a decision to
revisit with a reason, not a number to tune so a demo shows something.

## What this plan does not answer

- **Where the window is configured.** `default-window` is a var; per-table windows are deferred
  until someone wants a different answer for one table. The report makes that visible before it
  becomes a guess.
- **"Reclaim all reclaimable."** Deliberately absent — a single button over an irreversible
  operation is a different risk conversation. Revisit if per-table proves tedious.
- **Reclaiming catalog space.** `catalog.duckdb` never shrinks and was 98% of the lake at fixture
  scale. That ratio inverts at the sizes this feature is for, but shrinking the catalog is a
  separate problem with a separate mechanism.
- **The orphan window.** A `put-rows!` whose caller dies between the lake commit and `sub/commit!`
  leaves an orphan. This plan *reclaims* those but does not prevent them; they cannot be prevented
  without atomicity across two stores, which loci does not have.
