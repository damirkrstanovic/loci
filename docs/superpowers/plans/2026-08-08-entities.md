# Entities — a world for the facts to hang on

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.
> Steps use checkbox (`- [ ]`) syntax. Reviewers **measure**; implementers **prove their
> tests bite** (break the fix, watch the test fail, restore).

**Goal:** the `:entities` already recorded on every fact become something you can see, click,
search for, open, and — when you act on one — a citizen of the substrate; and a fact about a
subject reaches a notebook that shares that subject but not its lineage.

**Spec:** `docs/superpowers/specs/2026-08-08-entities-design.md` (approved in brainstorming,
2026-08-08). Read it first. This plan implements §§1–6 and §8 minus aliases — see
**Out of scope** at the foot.

**Architecture:** an entity is **derived**, not stored. `loci.entities` is a pure projection
over live facts — normalize, index, document-frequency, detect-in-text — and everything else
reads it. Facts are never rewritten and never store an object id, which is what makes
materialization safe to undo. Recall gains a *union* (lineage ∪ subject) plus inverse-frequency
weighting on the entity term, so widening the candidate set does not widen what wins.

**Tech stack:** Clojure (`src/loci/`), `clojure -M:test`; the shell is one file,
`resources/public/index.html`, tested by `npm run test:browser` (Node's runner +
playwright-core). **Both suites must pass.** `clojure -M:test` does not mean "all the tests".

---

## The invariant to protect, in one line

**A fact references an entity by its normalized name, never by an object id.** So `undo!` of a
materialization returns the entity to being a projection and touches no fact. Any reviewer who
sees a fact record gain an `ent:N` should reject the task.

```clojure
(ns loci.entities
  "The entity projection — a subject for the facts to hang on.

   An entity is a **normalized name**, the live facts that mention it, and
   nothing stored. This whole namespace is a pure function of a fact sequence,
   rebuildable from memory.edn alone exactly as `touched` is rebuildable from
   `events`, and it holds no store, no memory and no atom: the half that can
   walk the substrate passes facts in, and this half answers.

   **Normalization is lowercase + trimmed + internal whitespace collapsed, and
   nothing cleverer.** It must be *stable*: changing it re-identifies every
   entity, so the rule is written here and in the design, and changes only with
   a migration.

   Facts are NEVER rewritten to point at entity ids. They keep their `:entities`
   strings, and that is the property that makes materialization safe to undo."
  (:require [clojure.string :as str])
  (:import [java.util.regex Pattern]))

(defn normalize
  "The stable identity of an entity name: lowercase, trimmed, internal
   whitespace collapsed. nil and blank normalize to \"\"."
  [s]
  (-> (str s) str/trim str/lower-case (str/replace #"\s+" " ")))

(defn index
  "name → set of fact ids, over the **live** facts you pass in.

   Tombstones are the caller's problem — `mem/all-facts` already removes them —
   but a record with no `:entities` contributes nothing rather than throwing, so
   a caller that slips one in degrades quietly instead of failing a page load.
   A blank name is dropped: it is not a subject."
  [facts]
  (reduce (fn [m f]
            (reduce (fn [m e]
                      (let [n (normalize e)]
                        (if (str/blank? n) m (update m n (fnil conj #{}) (:id f)))))
                    m (:entities f)))
          {} facts))

(defn df-map
  "name → how many live facts carry it. The denominator of the inverse-frequency
   weighting, and it is **global on purpose**: computed over a scoped subset,
   `united states` would look rare inside the one notebook that talks about it
   and would go straight back to acting as an anchor."
  [facts]
  (update-vals (index facts) count))

(def ^:private promotion-threshold
  "Live facts a name needs before it is something you can open. Two, because on
   the measured corpus 68 of 104 names appear exactly once — a world made of
   every extracted string is two-thirds noise.

   A name is *known* from its first extraction (it is in `index` and it is
   matched by `detect`); this only governs what gets a place of its own."
  2)

(defn promoted
  "The names that are entities: enough live facts, or already materialized.

   **A materialized entity never demotes.** Once it is an object in the world it
   stays one regardless of the evidence — it is yours, not the evidence's."
  [idx materialized]
  (into (set materialized)
        (keep (fn [[n ids]] (when (>= (count ids) promotion-threshold) n)))
        idx))

(defn- bounded
  "`name` as a pattern that will not match inside a longer word — so \"us\" does
   not match \"thus\". The name is quoted, because it comes from a model and may
   contain regex metacharacters."
  [name]
  (re-pattern (str "(?<![\\p{Alnum}])" (Pattern/quote name) "(?![\\p{Alnum}])")))

(defn detect
  "The names present in `text`, longest match first.

   Every extracted name is eligible, not only the promoted ones: a name with one
   fact behind it is still what the question is about, and refusing to match it
   would make the union useless in exactly the case it was designed for.

   **No new extractor and no model call.** The name list is already in hand, and
   a second extraction path would be a second thing to be wrong.

   Longest-first with blanking, so `wrath of the righteous` wins and `wrath` does
   not also match the same words. Blanking replaces every occurrence, or a second
   mention of the long name would re-expose the short one."
  [names text]
  (let [t0 (normalize text)]
    (if (str/blank? t0)
      #{}
      (loop [ns  (sort-by (juxt (comp - count) identity) (remove str/blank? names))
             t   t0
             out #{}]
        (if-let [n (first ns)]
          (let [p (bounded n)]
            (if (re-find p t)
              (recur (rest ns) (str/replace t p (apply str (repeat (count n) \space))) (conj out n))
              (recur (rest ns) t out)))
          out)))))
```

**Change A — `scoped` unions.** `{:filter {:sources #{…} :entities #{…}}}`: a fact passes if it
was recorded against one of `sources` **or** carries one of `entities` (normalized names).

```clojure
(defn- shares-entity?
  "Whether `f` carries one of `names` — already-normalized entity names.
   Normalizing here rather than at the caller because a fact's `:entities` are
   stored exactly as the distiller wrote them and are never rewritten."
  [names f]
  (boolean (some names (map ent/normalize (:entities f)))))

(defn- scoped
  "The facts a query is allowed to see.

   `{:filter {:sources #{…}}}` narrows to facts recorded against one of those
   ids; `:entities` widens that back out to facts sharing a subject, and the two
   are a UNION — dropping lineage would stop a deep-dive child inheriting its
   parent's facts, an immediate regression. No `:filter` at all is no filter.

   **An empty `:sources` set is still an empty result** (with no `:entities`
   beside it): the caller asked for the facts belonging to a scope that owns
   none, and answering with the whole memory is the one failure a scope exists
   to prevent."
  [facts opts]
  (let [{:keys [sources entities]} (:filter opts)]
    (if (or sources entities)
      (filterv (fn [f] (or (and sources (in-sources? sources f))
                           (and entities (shares-entity? entities f))))
               facts)
      (vec facts))))
```

**Change B — inverse-frequency weighting, and the subject set scores.**

```clojure
(defn- relevance
  "How well `f` matches the query, before recency and strength: 0.6 of the
   keyword overlap plus 0.4 of the entity overlap, in [0, 1].

   The entity half is weighted by **inverse document frequency**: each name
   counts 1/(live facts carrying it), so `united states` — 6 facts across three
   unrelated subjects on the measured corpus — stops acting as an anchor and a
   name mentioned twice dominates. With every name equally frequent this is
   exactly the fraction it replaced, which is why nothing else had to move.

   A fact's entities are matched against the query tokens AND the subject set.
   The subject set is what carries a multi-word name: `qt` is single words, so
   `wrath of the righteous` could never match a token and the fact it identifies
   would score 0 on the half that exists to find it."
  [qt subjects dfm f]
  (let [kw  (jaccard qt (tokens (:fact f)))
        es  (set (map ent/normalize (:entities f)))
        w   (fn [e] (/ 1.0 (double (max 1 (get dfm e 1)))))
        tot (reduce + 0.0 (map w es))
        hit (set/intersection es (set/union qt (set subjects)))
        ent (if (pos? tot) (/ (reduce + 0.0 (map w hit)) tot) 0.0)]
    (+ (* 0.6 kw) (* 0.4 ent))))

(defn- score [qt subjects dfm now f] (* (relevance qt subjects dfm f) (weight now f)))
```

```clojure
          all        (live (vals @!facts))

          dfm        (ent/df-map all)
          subjects   (into #{} (map ent/normalize) (:subjects opts))
          candidates (scoped all opts)
```

```clojure
(defn subject-set
  "The subjects a recall in `space` is about: the names detected in the prompt,
   plus every name already carried by a fact in this lineage.

   The second half is what makes a notebook that has been working on something
   keep reaching the rest of what is known about it; the first is what makes a
   BRAND-NEW notebook work, which is the reported case — ask about the game

          (comp (mapcat :entities) (map ent/normalize) (remove str/blank?))
```

```clojure
(defn entity-object
  "The materialized object for a normalized entity name, or nil. Matched on
   `[:value :name]`, never on the title: the title is a display string and an
   edit to it must not re-identify the entity."
  [st name]
  (first (filter #(and (= :entity (:kind %)) (= name (get-in % [:value :name])))
                 (vals (sub/objects st)))))

(defn materialized-names
  "The normalized names that already have an object, so `ent/promoted` can be
   told which entities never demote."
  [st]
  (into #{} (keep #(when (= :entity (:kind %)) (get-in % [:value :name])))
        (vals (sub/objects st))))

(defn entity-payload
  "The entity page: the subject, the live facts that mention it ranked by the
   ordinary recall score, and the objects and notebooks those facts came from.

   `:semantic? false` — the candidate set is already exactly the facts carrying
   this name, so meaning has nothing left to decide, and this is a page load.
   `:subjects` carries the name because a multi-word one matches no query token
   and its own facts would otherwise score 0.

   `:promoted` false with facts present is a real state and must render: a merge
   can push a name back below the threshold, and the page should say so rather
   than vanish."
  [st m raw-name]
  ;; `nm`, not `name` — a local called `name` shadows clojure.core/name, which
  ;; the `:kind` line below needs
  (let [nm  (ent/normalize raw-name)
        all (mem/all-facts m)
        idx (ent/index all)
        obj (entity-object st nm)]
    (if (str/blank? nm)
      {:error "no entity name given"}
      (let [hits (mold/recall m nm {:k 50 :semantic? false :subjects #{nm}
                                    :filter {:entities #{nm}}})
            srcs (->> hits (mapcat mem/source-ids) distinct
                      (keep #(when-let [o (sub/object st %)]
                               {:id (:id o) :title (:title o) :kind (name (:kind o))}))
                      vec)]
        (cond-> {:name     nm
                 :count    (count (get idx nm #{}))
                 :promoted (contains? (ent/promoted idx (materialized-names st)) nm)
                 :facts    (mapv #(dissoc % :vec) hits)
                 :sources  srcs}
          obj (assoc :object (:id obj)))))))
```

### Task 5: Materialization — one object, one notebook, one undo

**Files:**
- Modify: `src/loci/server.clj` — new `materialize-entity!`, new route
- Test: `test/loci/server_test.clj`

The page is computed until you act on it. The one action is **New notebook about this**, and it
creates the `:kind :entity` object and the notebook about it in **one `:tx`**, so `undo!` — which
pops one commit — reverses both.

```clojure
(defn materialize-entity!
  "POST /api/entity-notebook {\"name\": \"tsmc\"} — the entity becomes a citizen.

   ONE `:tx`: the `:entity` object carrying the normalized name, the notebook
   about it, and the cell that puts one in the other. `undo!` pops one commit, so
   the gesture is reversed whole.

   **No fact is touched, and no fact learns this object's id.** A fact references
   the identity — the normalized name — so undoing this returns the entity to
   being a projection with nothing left dangling. That is the whole reason the
   model is derived, and it is the invariant to protect in review.

   Materializing an already-materialized name is not an error and mints nothing:
   it answers with the object that is already there. The page is reached by name,
   and two objects for one name would make `entity-object` a coin toss."
  [st name*]
  (let [name (ent/normalize name*)]
    (cond
      (str/blank? name) {:error "no entity name given"}
      :else
      (if-let [o (entity-object st name)]
        {:state (state-payload st) :entity (:id o)
         :spaceId (first (keep #(when (and (= :space (:kind %))
                                           (contains? (nb/refs-of %) (:id o)))
                                  (:id %))
                               (vals (sub/objects st))))}
        (let [eid (next-id st "ent:")
              sid (next-id st "space:about-")
              eobj {:id eid :kind :entity :title name :value {:name name}}
              sobj {:id sid :kind :space :title name
                    :value {:intent (str "everything about " name)
                            :cells [{:ref eid}]}}]
          (sub/commit! st {:op :tx :events [{:op :put :id eid :value eobj}
                                            {:op :put :id sid :value sobj}]})
          {:state (state-payload st) :entity eid :spaceId sid})))))
```

Route:

```clojure

                                      (json-resp (materialize-entity! st name)))
```

```js
// The entity page. Drawn from `/api/entity?name=` into the modal, and from
// `/api/mold`'s `rendered` into the molder once the entity is an object — ONE
// payload shape and one renderer, or the page would quietly become two pages.
function renderEntityPage(p){
  const facts=p.facts||[], srcs=p.sources||[];
  let h='<div class="entname">'+esc(p.name)+'</div>'+
    '<div class="entmeta">'+facts.length+' fact'+(facts.length===1?'':'s')+
    (p.promoted?'':' · not yet a subject of its own — a merge can collapse the evidence')+'</div>';

    ? facts.map(f=>'<div class="memfact"><div style="font-size:13px">'+esc(f.fact)+'</div></div>').join('')
    : '<div style="color:var(--muted);font-size:13px">Nothing is remembered about this yet.</div>';
  if(srcs.length) h+='<div class="entsrc">from '+srcs.map(s=>
    '<span class="ghostchip" data-open="'+esc(s.id)+'">'+esc(s.title||s.id)+'</span>').join(' ')+'</div>';
```
